# 旅行知识与行程维护

用于持续维护同一套旅行资料。先读已有资料，识别这是了解目的地、筛选、细化攻略、调整计划、记录经历还是请求复盘；只处理本轮有变化的部分。

正式项目流程与目录见 [workflow.md](../../docs/workflow.md)，字段与命令见 [data-model.md](../../docs/data-model.md)。`travel/` 只放真实资料；`tests/fixtures/`、`tests/evidence/` 和 `tests/output/` 只作测试，不把模拟决定迁入真实行程。

## 信息放在哪里

- 每个景点一个稳定 ID 和文件夹，别名归到同一条记录；查询现有 ID 与别名后再新增。
- 景点知识源存事实、来源、核实日期与建议；旅程源只引用 ID，存选择、取消、顺序、时段和理由。取消只改变本次参与状态，保留知识。
- 酒店、机场等落脚点单独存为 anchor，不占景点编号。确认具体酒店与坐标来源；航班未知时，机场终端标为待确认，进城、日游、离城分别规划，不假定同一天发生。
- 实际经历写独立 notes；偏好、预计体验、模拟结果不能当成去过或真实感受。
- 目的地知识放 `travel/destinations/<id>/`，旅程需求/筛选/日程放 `travel/trips/<id>/`。`selection.json` 是筛选意向，`days/` 是具体安排；取消某天不等于永久排除。实际经历用 `journal/`，按需复盘用 `reviews/`。
- 自动生成的攻略和地图是视图。改源数据再重建，不靠逐文件手改维持一致。生成器不改用户笔记。

## 按阶段工作

1. **从未知到初步认知**：先给目的地地理分区、体验类型、季节或时间限制、文化背景及代表候选。先用一页概览建立认知，不为所有候选做完整攻略。
2. **筛选**：对照旅伴、兴趣、体力、时段、预算、交通、饮食等约束，记录选中、候补、取消和理由。事实不足写待确认，不捏造评分或用户偏好。
3. **细化入选点**：覆盖交通/入口、费用/开放、食物、购物、拍照、装备、语言、文化观察。沿用仍适用的已有来源；出行日期确定后优先复查时效性信息和冲突。
4. **对话变更**：把对话转为有限的源数据变化，并记明模拟或实际决定。取消后同步活动列表、编号、连线、预算和休息段；改时段后重审日落、营业、光线、接送与饮食安排。用户可调整计划，地图不会自动求最优路线。
5. **旅行中**：记录实际去过什么、花费、观察和用户表达，不擅自把原计划写成已完成。
6. **复盘**：仅在用户请求时，使用 [review.md](assets/review.md) 写入对应旅程 `reviews/`；比较计划与实际，说明做过的选择、依据、文化认识及下次改进，引用记录日期。没有记录的部分保持未知；普通攻略更新不重写复盘。

## 同步与验证

正式命令入口为项目 `scripts/travel.py`，底层为 [travel_sync.py](scripts/travel_sync.py)，适配说明见 [schema.md](references/schema.md)。创建目的地/旅程优先用入口命令；资产目录是唯一模板源：`place.json`、`anchor.json`、`trip.json`（整次旅程）、`day.json`（单日）、`traveler.md`、`destination.md`、`decisions.md`、`journal-entry.md` 与 `review.md`。空草稿合法，不预填模拟景点或旅伴。只有填好当天景点/时段并设为 ready 才生成。

道路模式先读取已有缓存，缺少新方向或新坐标的路段时再请求路线服务。当前复用 OSRM/FOSSGIS 汽车路线；请求需有 User-Agent、串行间隔至少一秒。保留请求 URL、方向、坐标、获取时间及原始响应；往返分别查询，不能直接反转路线。刷新缓存后重新生成所有受影响视图。道路数据缺失或无效时停止生成，不自动退回直线。路况、候车、车费及机场手续时间均不由道路模型推断。

变更后对受影响日期运行 `build --trip <id> --day <id>` 再 `check`，实际查看静态地图。入口同时更新预览副本。输出清单绑定所引用源数据及生成器摘要，并检查输出文件散列；旧图、篡改图或缺项应报错。报告实际执行的验证，不把“计划验证”写为通过。重复构建应无字节差异；未入选的草稿候选不阻塞已确定行程。

涉及地图行为变更时，使用仅绑定回环地址且只暴露地图输出目录的本地 HTTP 服务，实际打开 HTML。检查底图与脚本加载、景点编号、弹窗时间、酒店/机场、路线分层和缩放；取消和重排后分别复核并保留截图。HTML 内容校验不能替代浏览器运行验证。无地图行为变更时无需重复完整浏览器验收。

点位用有来源的经纬度，GeoJSON 顺序为经度、纬度；入口与地标代表点要区别。只有经过路线服务或核实的轨迹才可称道路路线。直线只能标为顺序示意，不能据其长度推断驾车或步行时间。地图服务、坐标数据和图片分别保留适用归属。

若资料冲突或过时，保留来源和日期，明确影响哪个决定；不把未知费用按免费、不把常规开门时间当成所有展馆开放。已知小计与总预算分别表达。

## 已验证边界

配套脚本已验收单日、三个景点的取消和顺序调整、Markdown/GeoJSON/PNG/HTML 同步，以及酒店/机场、OSRM 汽车道路、缓存检测和 HTML 浏览器交互。开发母项目证据在 `tests/evidence/`；干净模板不携带验收数据。路线是道路模型参考，不是实时导航。费用仍为 MYR 已知门票小计。目录可放多个日计划和旅程，生成器逐日运行；QGIS、步行/公交、自动优化、跨日/跨目的地与大量点位仍未验收。静态布局超过三个景点需改版和验图。运行脚本不等于事实已经重新联网核实。
